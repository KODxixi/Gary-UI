向两个最成熟的
设计体系学到底

Apple Human Interface Guidelines 与 Google Material Design 3，各自在数十亿设备上被反复验证。把它们的规则、数值和共识提炼成可执行的设计规范——这就是 Gary-UI 的审美基线。

Apple · Human Interface Guidelines Google · Material Design 3

当两套体系在同一件事上给出相同答案，那不是风格选择，而是经过十亿级验证的设计铁律。

01 / PRINCIPLES

设计原则

所有具体规则都从顶层原则推导。先定审美哲学，再谈字号像素。

Apple
Human Interface Guidelines
  • Clarity · 清晰：文字在每种字号下都清晰可读，控件明确
  • Deference · 顺从：内容是主角，界面让位、不抢戏
  • Depth · 纵深：层级通过层次与运动传达（Liquid Glass 用材质折射）
  • 整个 app 保持一致的设计语言，靠熟悉感降低学习成本
Google
Material Design 3 · Expressive
  • Bold · 大胆：醒目、有主见的视觉表达
  • Expressive · 表现力：用颜色、字体、形状表达品牌个性
  • Adaptive · 自适应：一套设计覆盖所有设备与尺寸
  • Material 是受物理启发的数字材质：有厚度、光影、触摸反馈
= 两者共识 · 铁律
  • 清晰永远第一：先保证可用、可懂，再谈好看
  • 内容是主角，chrome（界面外壳）让位，一切为阅读与操作服务
  • 层级靠结构——字重、间距、光影，而不是靠装饰与颜色堆砌
G Gary-UI 落地
  • 每屏开工先问：这一屏要让用户做什么？
  • 层级只用字重 / 间距 / 纵深表达，禁止颜色堆砌
02 / TYPOGRAPHY

排版

排版是层级与信息密度的第一工具。高手靠一套克制的字重做全部层级，新手靠颜色和字体。

Apple
Typography
  • 系统字体 SF Pro（Sans）/ New York（Serif）
  • iOS 正文 17pt（最小 11pt）；macOS 13pt（最小 10pt）
  • 避免 Light / Thin；正文用 Regular，强调用 Medium / Semibold
  • 大字用 Display、小字用 Text（optical size 自动切换）
  • 支持 Dynamic Type，字号随用户系统设置缩放
Google
Typography
  • Roboto（可换 Roboto Flex 可变字体）
  • 15 baseline + 15 emphasized 样式；emphasized 字重更高
  • 五角色：Display / Headline / Title / Body / Label
  • brand 字族管大字（表达）、plain 字族管小字（易读）
  • Display L 57/64 · Headline L 32/40 · Title L 22/28 · Body L 16/24 · Label L 14/20
层级示范
LABEL · 标签
Display 标题
Title 次级标题
Body 正文：清晰、克制、可长时间阅读。所有数字默认 tabular-nums 对齐：0123456789。
= 两者共识 · 铁律
  • 一套克制字重做全部层级：正文 400，标题 600–700；大字重表达、小字重易读
  • 大标题对比度 ≥ 3:1，正文 ≥ 4.5:1；数字一律 tabular-nums
  • 字体族 ≤ 2：一个标题、一个正文，不堆字体
G Gary-UI 落地
  • 双字族：Space Grotesk 标题 / 系统正文
  • fluid type scale（视口 390→1440 连续缩放）
  • 中文行高按 Medium 语言，比拉丁高约 7%
  • 大标题负字距 -0.025em，标签正字距 0.01em
03 / RICH TEXT

富文本与内容样式

标题、正文、引用、列表、代码、链接——这些富文本元素必须语义化、有统一节奏，长文才能舒服地读下去。

Apple
Content & Text styles
  • 文本样式语义化：标题 / 正文 / 引用 / 代码 / 列表各司其职
  • 长段落控制行宽、留足行距，避免一行拉太长
  • 链接与强调克制，避免满屏高亮、满屏加粗
  • 标题与正文之间留白，形成可扫读的节奏
Google
Editorial treatments
  • Body 管长文、Label 管标签，角色不混用
  • 长文本限制 measure，左对齐为主（不居中长文）
  • 列表与段落节奏统一，间距符合基准网格
  • 用列表与短段落代替大段密文，提高可扫描性
= 两者共识 · 铁律
  • 富文本元素语义化、全 app 一套样式，不随手写
  • 行宽 65–75ch，正文行距 1.5–1.7
  • 段落间距 > 行间距，用垂直留白制造阅读节奏
G Gary-UI 落地
  • prose 原语：measure / 垂直节奏 / 标题配对
  • blockquote / code / list 统一语义样式
04 / LAYOUT

布局

布局靠统一基准单位与内容驱动的自适应，而不是为每种屏幕写死一套。

Apple
Layout
  • Auto Layout / SwiftUI：约束驱动，而非绝对坐标
  • 安全区 + 布局指南（safe area / layout margins），内容不贴边
  • 内容填满屏幕，重要内容优先、放在前
  • 用 size classes 适配横竖屏与设备，一套布局自适应
Google
Responsive layout
  • 4dp 基准网格：所有尺寸是 4 的倍数
  • spacing：4/8/12/16/24/32/40/48/56/64/80
  • 断点：Compact <600 · Medium 600–840 · Expanded 840–1200 · Large 1200–1600
  • pane 布局：list-detail / supporting / feed
= 两者共识 · 铁律
  • 统一基准单位：Apple 用 8pt grid、Google 用 4dp grid，间距不成倍数即错
  • 边距 / 安全区，内容永不贴边；内容驱动断点，一套布局自适应
G Gary-UI 落地
  • 布局原语：stack/cluster/switcher/grid/sidebar/center/cover
  • fluid space scale，容器驱动（无媒体查询）
05 / ALIGNMENT

对齐关系

对齐是"高级感"最隐蔽的来源。同级元素对齐到同一列、同一基线，界面立刻整洁。

Apple
Alignment
  • 所有元素互相对齐：整洁、可浏览、有秩序
  • 用缩进表达层级（indentation = hierarchy）
  • 非对称图标做 optical 对齐：加内边距让视觉居中
  • 文字与图标基线对齐，不悬空
Google
Alignment
  • 所有元素对齐到 4dp 网格
  • 同列内容左对齐，数值列右对齐
  • 关键内容对齐到同一基线，避免视觉参差
= 两者共识 · 铁律
  • 正文左对齐为主，避免居中长段落；同级元素对齐到同一列 / 基线
  • 图标做 optical 居中、数字做 tabular-nums 对齐，"看着齐"才是真的齐
G Gary-UI 落地
  • 统一对齐网格，禁止元素随意偏移
  • 非对称图标 optical 居中，数字默认 tabular-nums
06 / CARDS

卡片

卡片承载"单一主题"的内容与动作。它是分组工具，但绝不能滥用——留白和分隔线更简单时就不该用卡。

Apple
Containers & grouping
  • 用背景形状 / 材质 / 分隔线对相关项分组
  • 内容与控件分离，卡片内层级清晰
  • 圆角用 continuous corner（同心连续圆角）
Google
Cards
  • 三变体：Elevated（阴影）/ Filled（填充）/ Outlined（描边）
  • 一卡一主题，易扫描，可作详情入口
  • 以 grid / list / carousel 成组出现
  • 留白 / 标题 / 分隔线更简单时，不要硬塞卡片
圆角跟随卡片尺寸 · 恒为方形角
30px · 大卡
22px · 中卡
15px · 小卡
= 两者共识 · 铁律
  • 一卡一主题，卡内层级清晰；三种强调：填充 / 描边 / 抬高
  • 圆角跟随卡片尺寸（大卡大圆角、小卡小圆角），且四角恒为方形角
  • 不过度用卡：分组更简单的方案（留白 / 分隔线）优先
G Gary-UI 落地
  • 卡片表面渐变 + edge + inset 高光，三档 elevation
  • adaptive-radius.js：按元素自身宽度算圆角，恒方形
07 / BUTTONS

按钮

按钮承载动作。每一视图只突出一个主按钮，其余靠样式降权；区分主次靠 style，绝不用 size。

Apple
Buttons
  • 点击区 ≥ 44×44pt（visionOS 60×60）
  • 自定义按钮必须有 press state，否则显得无响应
  • 用 style 而非 size 区分主次；同组选项同尺寸
  • 突出按钮每视图 1–2 个，多了增加认知负担
  • Role：Normal / Primary / Cancel / Destructive（系统红，且不可做主按钮）
  • 标签动词开头、简短：Add to Cart；打开新窗口加 省略号…
Google
Buttons
  • 五种：elevated / filled / tonal / outlined / text
  • filled 给最重要动作，其余逐级降权
  • 不要堆满按钮，次要动作收进 menu / chips / link
  • 宽度适应标签、不窄于文字；高度 40dp（触控 48dp）
按钮层级（由强到弱）
Primary Secondary Outlined Text Delete
= 两者共识 · 铁律
  • 每视图主按钮 1 个（最突出）；主次靠 filled→tonal→outlined→text，不靠 size
  • 点击区 ≥ 44，必须有 hover / press 状态；destructive 用红且不可做主按钮
G Gary-UI 落地
  • primary / secondary / ghost 三档，语义化 role
  • 点击区 44px，标签动词开头、短
08 / ICONS

图标

图标是"单个概念"的视觉速记。一套图标必须在风格、线宽、细节上完全统一，且与相邻文字线宽一致。

Apple
SF Symbols
  • SF Symbols（glyph），与文字同字重
  • 极简、用通用隐喻，细节可辨
  • 全套图标在大小 / 细节 / 线宽 / 透视上统一
  • 非对称图标 optical 对齐；选中态交给系统
Google
Material Symbols
  • Material Symbols：outlined / rounded / sharp 三种风格
  • 四轴可变：fill / weight / grade / optical size
  • 状态用 fill、强调用 weight，不换图标
= 两者共识 · 铁律
  • 单一风格 / 线宽；图标与相邻文字线宽一致，视觉才是一套
  • 状态变化用 fill / weight 表达，不换图标；非对称图标 optical 对齐
G Gary-UI 落地
  • morph-icons（morph 状态切换）为默认图标机制
  • 统一线宽，图标与文字同字重
09 / COLOR

配色

颜色用语义化角色而非写死色值：中性色分层、算法保证对比、深浅一套语义，强调色克制使用。

Apple
Color
  • system colors 语义化（systemBlue / systemRed…）
  • 背景三级：primary / secondary / tertiary，分层承载内容
  • 浅色 / 深色自适应，同一套语义颜色
  • 品牌 / 强调色克制使用，不铺满屏幕
Google
Color system
  • 26+ color roles：primary / secondary / tertiary / error / surface…
  • tonal palettes 算法生成，深 surface 自动配浅 text
  • Dynamic color：从壁纸 / 内容生成可达配色
  • 三级 contrast（standard / medium / high），内置深色主题
= 两者共识 · 铁律
  • 颜色语义化角色，不直接写死色值；中性色分层（page / surface / card / plate）
  • 算法保证对比（正文 ≥ 4.5:1）；深浅一套语义，强调色克制
G Gary-UI 落地
  • tinted neutrals：oklch 带 255 蓝相，中性色不死黑
  • 语义化 color roles，双模式，对比度自动达标
10 / MOTION

动效

动效只为反馈、层级与状态服务，绝不炫技。时长语义化，全程尊重 reduced motion。

Apple
Motion
  • 动效服务层级与状态，不为炫技、不分散注意
  • 物理感、自然（spring 弹性），符合真实世界
  • 必须尊重 reduced motion，用户可关闭
Google
Motion
  • motion tokens：duration + easing，统一调用
  • 标准 / 强调 / 退出三模式，时长分级
  • 过渡清晰表达层级变化与空间关系
= 两者共识 · 铁律
  • 克制、目的明确：每段动效都要回答"它在传达什么"
  • 语义化时长：反馈 ~120ms / 进入 ~240ms / 退出 ~150ms
  • 全程支持 reduced motion
G Gary-UI 落地
  • 三档 motion 语义 + 统一 easing（out / in）
  • reduced motion 活策略，默认短时长、不炫技
