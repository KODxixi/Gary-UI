# 图示规范参考实现

`reference.html` 是 [docs/DIAGRAM_EXPRESSION.md](../../../docs/DIAGRAM_EXPRESSION.md) 的完整实例，不是设计稿。它用一张真实图同时演示规范里每一条可判定的规则，供复用与验收时对照。

## 它演示了什么

| 规则 | 在这张图上怎么看 |
|---|---|
| §3.1 唯一主路径 | 左→右一条主干：设计师 → console → 网关 → Core → Agent Gateway；所有分支从主干节点离开 |
| §3.2 分块是状态命题 | 两个分块标签是陈述句：「ArchOS 控制面 · 已齐备」「执行体 · 稀疏」，直接指出缺口在哪一侧 |
| §3.3 分块与卡片是两层 | 分块是虚线细边框 + 5% 填充；卡片是实线边框 + 20% 填充，强度不同 |
| §3.4 节点只写事实 | 节点名是 `packages/core` / `HTTP :7701` / `registerLocalExecutor`；状态另置在 tag |
| §3.5 线型管成立性 | 已接通的执行器是实线，未接入 / 外部是虚线；线色不管这个 |
| §4 分层着色 | 底 `#141414` 纯 K；分块取块族色 46%；卡片取分组色 20%；线色取目标节点分组色；文字全中性 |
| §5 状态词闭集 | 四个执行器分别是「已接通 / 仅模型通道 / 未接通 / 拟接入」，无一自创 |
| §6 跨边界必须绕行 | Hermes 执行器在分块外，连线从 Agent Gateway 底部绕出再回来——绕行长度就是「还没纳进来」的证据 |
| §7 卡片与图同源 | 三张结论卡的每一条都能回指图上节点或 `adapters/README.md` 的执行器表 |

## 怎么复用

1. 复制 `reference.html`，替换节点、文案与分组色。
2. **不要改**：分层强度（§4 表格）、状态词闭集（§5）、跨边界绕行（§6）、主路径唯一（§3.1）。这四条是规范本身，改了就不再是同一套语法。
3. 分组色从 `spec/chart-recipes.json` 的 `themes.dark.category1..8` 里取，按职责分配，同类对象同色。
4. 改完用真实浏览器打开，检查：背景是 `rgb(20,20,20)`、箭头颜色跟随父线、无横向溢出。

## 验收

- 静态：文件自包含，无外链、无脚本依赖。
- 视觉：`document.body` 背景必须是纯 K（`#141414`，R=G=B）；分块、卡片、连线三层强度肉眼可分。
- 语义：对照上表逐条过一遍；任一条做不到，图就是草稿。
