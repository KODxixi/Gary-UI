# Gary-UI 图表与分析图配色

Gary 的数据颜色负责区分对象、表达数量和说明状态。先决定颜色承担哪种含义，再选择色板；中性界面、清楚的数据标记和稳定的文字层级共同形成整体观感。

**颜色数值唯一维护于 [spec/chart-recipes.json](../spec/chart-recipes.json) 的 `themes`。** `colorSystem` 只用角色名组织色板、状态和任务约定；本文不复制十六进制值。图表选型、数据、尺度和标注仍按 [CHART_EXPRESSION.md](CHART_EXPRESSION.md)。

## 1. 官方原则与 Gary 决定

Apple 建议颜色服务于信息理解，同时保留形状、图案或文字；相邻色块可增加分隔，帮助识别边界。Gary 将它用于直接标注、线型／点形、分段边界和可访问明细，而不要求用户记住某种颜色代表什么。[Apple HIG Charts](https://developer.apple.com/design/human-interface-guidelines/charts)

Apple 的颜色指南同时强调外观模式、对比度和文化语境。Gary 因此为深浅模式分别配色，并要求涨跌、风险等约定在当前任务中声明。[Apple HIG Color](https://developer.apple.com/design/human-interface-guidelines/color)

Google Material 3 将色相与用途分开：角色说明颜色用在哪里，前景与容器需要成对选择，深浅主题有各自的明度分配。Gary 借鉴这种角色管理方式，给图表单独建立颜色与底色、填色与标签的关系。[Google Android：Color for mobile design](https://developer.android.com/design/ui/mobile/guides/styles/color)

Google 的旧版 Material 色彩系统明确允许数据分类使用主界面主题之外的附加色。本次未获得可作为新版 M3 统计图分类／连续／偏差色阶标准的专门规则，不能把 Material 界面调色板说成 Google 推荐的图表色板。[Material 2：Additional colors for data visualization](https://m2.material.io/guidelines/style/color.html)

下面的具体颜色、六色／八色容量、七级色阶、角色映射与使用限制均为 **Gary 的设计选择**。它们没有照搬 Apple 系统色或 Material 预设，也不是 HCT 自动生成结果。对比度计算通过不代表每一对颜色都能被所有色觉状态区分。

## 2. 按颜色承担的任务选型

| 用途 | 机器入口 | 适用 | 禁用或替代条件 |
|---|---|---|---|
| 无序分类 | `colorSystem.palettes.categorical6` | 少量系列、互斥组成、具名模块 | 连续数值、等级强弱不能套六色；一个系列优先单色 |
| 必要的七至八类 | `colorSystem.palettes.categorical8` | 有足够空间直接命名的概览 | 密集交叉线或依赖小图例猜颜色时改小多图／条形／表格；八个色块不等于八类都可可靠辨认 |
| 从低到高的连续量 | `colorSystem.palettes.sequential7` | 强度矩阵、分箱热图、地图量值、从属的表内色阶 | 无序类别、具有真实零点的正负偏差不用；比较图不能各自随意归一化 |
| 围绕基准的正负偏差 | `colorSystem.palettes.diverging7` | 目标差、残差、相对基准变化 | 没有有意义的中点时不用；不能把蓝／陶色解释成坏／好 |
| 中性基线与上下文 | `colorSystem.neutralRoles` | 零点、目标、总量、背景比较 | 低对比网格不能代替重要边界；未知不能冒充零 |
| 已声明状态 | `colorSystem.semanticStates` | 达到、未满足、待核验、信息、未知 | 单凭数值正负或颜色好看，不能生成状态判断 |

每个色板包含 `roles`、`use`、`avoid` 和 `requiredRedundancy`；颜色通过 `themes[theme][role]` 解析。`sequential7` 从低到高排列：暗色底上强度越高越亮，浅色底上强度越高越深。两套保持数值方向一致，不反转数据，也不整图反色。

`diverging7` 从负侧极值经过中点到正侧极值，`centerIndex` 指定中性色。默认中性只代表准确的基准值；若用容差区间表示“接近基准”，必须给出带单位的容差，不能把小幅负值和正值悄悄涂成零。

### 分类：身份固定，排序可变

在规范化数据中保存稳定对象 ID 与颜色角色的绑定。排序、筛选、切换图型和导出只改变位置，不能重新按当前数组下标发颜色；新增对象不能导致已有对象集体换色。图例顺序跟随当前标记顺序，但映射保持不变。

六色与八色都需要名称。重叠折线还需点形或线型；相邻的堆叠／环形色块需要清楚边界。八色扩展增加了相近色系，更容易在色觉缺陷或灰度下合并，默认先尝试小多图。图中只有一个量时，使用 `primary` 或中性加一个重点，避免每根柱子一个颜色。

### 连续量：明度有序，分箱可复核

先声明字段、单位、值域以及等宽、分位数或业务分箱的依据。图例显示实际边界；零保留真实数值含义，缺测用文字加斜纹／空框表示。七级色阶的明度经过单调性检查，但没有声称视觉差异严格等距。

默认采用七个离散档位。确需连续插值时，渲染器必须记录插值方式并重新验证色阶顺序、最低对比度与打印结果。不得用彩虹色制造不存在的边界；只有当前比较口径要求时才变更色域。精确判断依靠数值和共同尺度，色深帮助扫描。

### 偏差：基准优先，符号独立于评价

先声明中点、正负含义和单位。比较同口径的偏差幅度时通常使用共同的对称范围；非对称范围必须显著说明。正负号、基准线与原值保留，即使颜色不可分辨仍能知道方向。

该色板的两侧用于“低于／高于基准”。延迟增加可能不利，收入减少也未必表示流程失败。是否有利取决于任务定义，不能由 `primary`、`negative` 或色阶自动推断。

## 3. 各类图表与分析图如何调用

`colorSystem.familyMapping` 按 17 个 `families[].id` 提供 `palette`、`defaultRole`、`rule`、`whenSingle` 与 `alternative`；条件选型另有 `choices`。这是 Agent 与渲染器的选用依据，不能把字段存在当作引擎已经自动选色。

| 图型／分析图 | 默认颜色组织 | 必须保留的第二通道 |
|---|---|---|
| 折线、面积、单系列柱形、直方图 | 单个 `primary`；参照用中性虚线；少量多系列才用分类色 | 系列名称、线型／点形、刻度；低透明面积保留实色边线 |
| 分组条形、百分比堆叠、环形组成 | 分类角色按对象 ID 绑定 | 图例／直接名称、精确值；相邻段的分隔和数据表 |
| 双轴组合 | 每个量一种已声明颜色，轴标签对应系列 | 柱／线编码区别、左右单位和范围；颜色不能暗示相关或因果 |
| 瀑布 | 增减量按 `taskConventions.defaultSignedChange`，总计中性 | 正负号、累计连接、真实总计；有利／不利另写依据 |
| 点图、散点、箱线图 | 单色为先；有明确分组才用分类色 | 分组名称、点形、轴和统计定义；不能用随机颜色冒充第三变量 |
| 热图、带色阶的数据表、量值地图 | 无中点用 `sequential7`，有基准用 `diverging7` | 数值／可访问明细、带单位的色条、缺测样式 |
| 雷达、小多图、区间／误差 | 同对象同颜色；参考中性虚线；区间用所属系列浅填充 | 维度／面板名称、参照身份、点形、边线及区间定义 |
| 真实周期或方向玫瑰图 | 单量用单色；额外量才考虑有明确色条的连续色 | 方向顺序、径向尺度、原值，不能只靠色深判大小 |
| 架构图、关系分析图、思维导图 | 中性结构与具名模块；需要时少量分类色 | 模块名称、关系标签、箭头／线型；边的颜色不得暗示未定义的强弱或状态 |
| 精确数据表 | 中性文字与稳定底色；少量从属的状态／数值色 | 原值、字段名、正负号、状态文字；不能只留一格颜色 |

关系图仍走 Archify、Markmap 等既有路径，分类色只区分具名对象；流程方向用箭头，依赖／异常用带名称的线型。没有量值和尺度时不用统计色阶。

## 4. 中性参照、状态与任务约定

`referenceNeutral` 是新图的安静参照色，搭配虚线和名称。既有五种 SVG 参考保留 `reference` 作为强调参照角色，兼容已确认的样本；它不是“所有参照都必须金色”的通用规定。`grid` 只用于次要读数辅助，必要零线、总计和关键基准使用足够对比度的角色。

`semanticStates` 同时提供角色、默认文字、图标名和准入依据。图标通过现有图标入口实现，不能用颜色圆点独自承载含义。图表中的低彩度状态样式不改写全局按钮、警告或焦点 Token。

| 状态 | 使用前提 | 不代表 |
|---|---|---|
| 信息 | 有对象和上下文的已命名记录 | 已核验或绝对正确 |
| 已达到 | 已声明条件满足或流程已完成 | 所有业务指标都好 |
| 待核验 | 指明待查证事项或注意条件 | 已经失败 |
| 未满足 | 明确失败条件或不利事项 | 单纯数值为负 |
| 未知 | 证据缺失，暂不能判断 | 零值、通过或失败 |

中国股票任务可显式选 `taskConventions.cn-stock` 的红涨绿跌；明确要求绿涨红跌的任务选择 `green-up-market`。不根据界面语言猜市场，也不把其中的红／绿复用成危险／成功。涨跌方向在颜色之外保留 `+ / −`、文字和原值。这是任务显示约定，不是交易判断。

## 5. 前景、填充、边界一起验收

阈值读取同一 JSON 的 `contrast`：普通文字至少 4.5:1；必要数据标记对相关相邻颜色至少 3:1。Gary 对图中说明与标签统一使用普通文字阈值。阈值判断用未四舍五入的结果，显示报告时才取小数。[WCAG 文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[WCAG 非文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)

- 在图表底色上，使用 `text`／`muted`；使用彩色标签时也要满足文字阈值。
- 在不透明色块上，从 `labelOnFill.candidates` 选择实际对比度更高的一项；选择后仍须校验。不能默认所有色块都压白字。
- 在透明填充或渐变上，先与实际底色合成，再计算标签与边界。背景、遮罩、打印纸色改变后必须重算。
- 淡面积与柱形渐变需要不透明边线或端点标记，数值端不能消失；边线对相关背景达到必要标记阈值。仅测渐变最深处不能判定整个图通过。
- 色块相接时，分别检查实际相邻颜色。必要边界可采用可见的分隔线或轮廓，但分隔线本身也要可辨；两个颜色分别对底色合格，不代表它们彼此可分。
- 连续／偏差色阶的低强度或中点色允许接近背景，但不能单独承担必要边界或小字。热图必须有图例、原值与必要边界；缺测使用独立样式。
- 浅色模式中的白色点芯依靠有对比度的系列描边识别，白色芯本身不构成必要标记通过证据。

### 当前色板的计算结果

以下为 2026-09-09 版本在不透明参考底色上的 sRGB 数学检查，具体颜色仍只在 `themes` 中维护。202 项检查覆盖角色存在、主角色与标签对比、填色标签候选、连续明度与偏差两侧顺序；**不是浏览器、色觉模拟或导出验收通过声明**。

| 检查 | 深色主题 | 浅色主题 |
|---|---:|---:|
| 正文对底色 | 17.456:1 | 15.457:1 |
| 次要说明对底色 | 7.409:1 | 5.078:1 |
| 必要角色最低值 | 5.753:1 | 4.535:1 |
| 八色分类最低值 | 7.196:1 | 4.535:1 |
| 主色按当前 `barTop` 合成 | 6.941:1 | 3.790:1 |
| 主色按当前 `barBottom`／`area` 合成 | 1.305:1 | 1.221:1 |

最后一行未满足必要标记阈值，因此该填充只作辅助，必须保留边线、端点和读数路径。数值记录随 `themes`、填充或底色变化而失效，不能沿用历史结果。

计算方法：先将 sRGB 通道线性化，求相对亮度，再用 `(较亮值 + 0.05) / (较暗值 + 0.05)`。透明层先按实际渲染的合成与插值规则得到最终颜色；上述透明示例采用 sRGB 通道 alpha 合成，复杂混合模式需针对实际输出重测。

### 色觉与灰度复核

对实际图形分别检查红色觉缺陷、绿色觉缺陷、蓝黄色觉缺陷与灰度状态。检查对象是相邻色、重叠线、图例和数值，不是只看色板截图。灰度下仍应能借助名称、点形、线型、图案、位置和明细完成原任务。若颜色混淆导致任务无法完成，减少系列或改小多图；增加饱和度不是通用修复。[Apple 不单靠颜色评估](https://developer.apple.com/help/app-store-connect/manage-app-accessibility/differentiate-without-color-alone-evaluation-criteria)、[WCAG 颜色使用](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html)

## 6. 调用与职责边界

调用顺序：确定颜色含义 → 选择色板／状态角色 → 在规范化数据保存 ID 映射或数值域 → 解析当前主题 → 同源生成图、图例和表 → 验证实际尺寸、透明合成、色觉与导出。主题切换只换角色值，不改变对象、数据、域或状态。

```js
const policy = await fetch('/spec/chart-recipes.json').then(r => r.json());
const theme = 'dark'; // 由当前页面主题提供；子路径部署解析项目根路径
const colors = policy.themes[theme];
const palette = policy.colorSystem.palettes.categorical6;

// 映射与规范化数据一起保存；这里的 ID 仅为调用示例。
const entityRoles = new Map([
  ['service-a', palette.roles[0]],
  ['service-b', palette.roles[2]],
]);
const colorFor = id => {
  const role = entityRoles.get(id);
  if (!role || !colors[role]) throw new Error(`缺少颜色绑定：${id}`);
  return colors[role];
};
// 既有 SVG/ECharts/关系图适配器显式使用 colorFor(id)，不复制 HEX。
```

这个示例只解析配色，不声称完成图表语义、标签、可访问性或导出验证。五种 SVG 参考模块支持的输入角色以其实际 API 为准；新增色板不会自动修改所有引擎、网页或导出配置。

| 权威源 | 负责 | 不由本次色板替换 |
|---|---|---|
| `tokens/tokens.json` | 全局文字、界面底色、玻璃、按钮、焦点和控件状态 | 全站材质与交互颜色 |
| `spec/scene-recipes.json` | 阅读／分析／展示场景、材料、动态与既有适配器默认 | 已批准 Demo 与既有引擎输出 |
| `spec/chart-recipes.json` 的 `themes`／`colorSystem` | 新图表的颜色字面值、角色映射和选色约束 | 业务事实、图表数据和统计口径 |

现有 `scene-recipes.colors.chartCategory` 仍是旧适配器的兼容默认。新图使用本规范时显式读取 `chart-recipes`，不复制两套数组，也不声称兼容数组已经自动同步。后续改造既有引擎须单独更新它的消费路径并回归；不以写一份色板代替完整接入。

数据主区维持 Solid；光影不改变语义色，前景不受折射或滤镜。分类色不染满卡片、背景和标题，连续色阶只覆盖承担量值编码的区域。鼠标装饰仍默认关闭，入口仍为独立的 `Background`。
