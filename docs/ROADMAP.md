# Gary-UI 路线图

Gary-UI 希望成为可复制、可运行、能持续深化的 UI 设计系统。以 [完整 Demo](../examples/demos/index.html) 讲解设计，再由共享规范、组件、模板与工具支撑复用。下面区分已有能力、已知问题与待讨论方向；不代表发布日期承诺。贡献方式见 [CONTRIBUTING](../CONTRIBUTING.md)。

## 已有基础

| 能力 | 当前入口与边界 |
| --- | --- |
| 六个完整情境页面 | [Demo 首页](../examples/demos/index.html)：业务分析、知识阅读、项目看板、管理层大屏、长篇报告与方案汇报。使用固定示例数据。 |
| 统一视觉与交互 | [Portal](../portal/index.html)、[设计规范](../DESIGN.md)、共享 Token、圆形工具图标与光学卡片；默认单一点网格，`Background` 文字入口与主题按钮分离。 |
| 可复制 HTML 起点 | [模板组合](../patterns/starting-points/index.html) 提供应用模式、页面、主题和材质选择。复制的骨架仍依赖项目资源服务，不等于离线单文件应用。 |
| 本地制图与导出 | [Visual Adapter](../adapters/visual/README.md) 路由 Archify、ECharts、Markmap、AntV Infographic、Mermaid 与 Lucide，保留原生源及受支持的导出格式。它不是通用拖拽编辑器。 |
| Agent 协作契约 | [协作白皮书](GARY_UI_AGENT_COLLABORATION_WHITEPAPER.md) 与 [SKILL](../SKILL.md) 支持直接实施及按需 Session；专项 Skill 接入与引擎能力分别记录。 |
| 可追踪验收 | [公开版验收](PUBLIC_RELEASE.md) 记录真实页面、菜单、主题、复制 HTML 的检查和中间失败。历史通过仅对应记录中的版本与范围。 |

## 优先关闭的数据问题

以下两项 P2 已复现，当前仍开放。详细步骤与原始证据见 [公开版验收单](PUBLIC_RELEASE.md)。

| 问题 | 关闭条件 |
| --- | --- |
| 分析页切换区域后，判断详情仍固定打开江苏事项 | 按当前区域生成详情；全部、上海、江苏、浙江分别验证判断、详情与表格一致，再切回全部复验。 |
| 分析页图表导出仍为固定全部区域产物 | 导出匹配当前筛选数据并标明范围；若保留固定样例，明确标注并提供与当前视图一致的出口。逐一比较四种区域、双主题的图表、表格、原生数据及 SVG/PNG。 |

两项修复都需要行为回归和实际导出检查。不能以通用 UI 测试、控制台无错误或历史截图作为关闭依据。

## 接下来讨论和深化的方向

按用户能否真正复用来安排优先级；具体方案先通过 Issue 和可运行例子讨论。

1. **复用体验**：从全新克隆开始验证安装、预览、复制和二次编辑，逐步减少机器环境假设。明确哪些资源需随页面一起带走，并改进常见失败提示。
2. **设计说明与可访问性**：让每个组件说明适用场景、排版尺度、状态和键盘行为，覆盖空数据、长文本、错误与加载状态；补充实体手机和 Safari 的实际验收。
3. **数据与导出契约**：在关闭 P2 的基础上，让筛选范围、图表、原生数据与导出采用一致的上下文，建立内容一致性的回归例子。
4. **图表、思维导图与动效**：深化中文长标签、复杂关系布局、层级折叠、主题转换和打印表现；为播放、暂停、重播、切页和 reduced-motion 建立可复现的生命周期检查。新增引擎前先说明现有工具不能满足什么需求。
5. **跨页面一致性**：把新场景对排版、卡片、图标和响应式行为的改进沉淀到共享实现，再反向检验完整 Demo、Portal 与模板。
6. **社区维护与版本演进**：逐步建立可重复的自动检查、发布说明与兼容性约定，让贡献者知道一个改动如何验证、何时会影响现有页面。

每项深化都应交付具体场景、可运行实现和独立证据。接受新的设计方向，也保留对现有视觉基线的明确取舍；不靠增加更多样式开关来替代设计判断。
