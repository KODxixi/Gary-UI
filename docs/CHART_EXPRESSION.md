# Gary-UI 分析图表表达规范

本规范把图表参考中的有效做法拆成可以迁移的视觉语法：让人看见数据、理解尺度、找到依据，再形成判断。它服务于经营分析、产品与工程监控、研究报告、项目比较和公共信息表达，不绑定房产、DDS 章节、某组颜色或某个网站的构图。

**[spec/chart-recipes.json](../spec/chart-recipes.json) 是图表参数与机器规则的真源。** 本文解释选择理由、适用前提和失败条件；字号、间距、笔画、对比度阈值、响应式条件以该文件为准，不在此重复一套数值。表面与动态沿用 [scene-recipes.json](../spec/scene-recipes.json)，数据工具沿用[视觉适配器](../adapters/visual/README.md)。若真源尚未覆盖必要参数，先补有依据的规则，不能凭一次截图发明永久默认。

## 1. 从参考提取语法，不复制业务结论

已提供的 GarchOS 五类图形适合观察“形状如何服务解释”。从这些参考提取的规则须能离开原行业成立；[09.09 跨域验证页](../demo0909.html)因此使用[独立案例输入](../examples/demo0909/cases.json)检验迁移，而不是保留原网站字段、结论与固定几何作为通用模板。

| 参考中有效的做法 | 为什么有效 | 可迁移的规则 | 不能照搬的内容 |
|---|---|---|---|
| 两种编码共用横向分组，重点区域带边界 | 读者可以对应同一对象，并知道解释指向哪里 | 同对象对齐；重点带绑定明确范围和依据 | 不能默认每次都上双轴；机会区间不是装饰，也不是通用阈值 |
| 总量由一段段增减衔接 | 看得到起点、变化路径与终点，贡献可以复核 | 同基准加总、增减标号、必要连接线 | 某行业的“三本账”、固定贡献和乐观情景不是通用数据 |
| 环图把整体拆成互斥状态，中心给摘要 | 局部与整体相邻，状态差别可以快速扫描 | 先确认分母与互斥关系；摘要说明是什么比例 | “就绪度”不等于准确概率；不能把任意指标放进圆环凑完整 |
| 雷达保留维度标签与参考轮廓 | 能看见各维的差距和形态 | 统一方向与尺度，逐维解释，参考值可追溯 | 不复制归一化分数、维度顺序或用面积决定优劣 |
| 玫瑰图保留真实方向及频率标注 | 环形位置有真实的周期／方向含义 | 只有环形变量才用极坐标；声明径向编码 | 普通类别不应为了好看绕成一圈；主导方向也不自动表示有利 |

这些手法共同形成以下七层。层次是阅读顺序，不要求七层都画成卡片或增加容器。Apple 强调数据标记优先、描述与轴提供上下文；Gary 将这一原则落实为明确的职责分工。[Apple Charts](https://developer.apple.com/design/human-interface-guidelines/charts)

| 层 | 负责什么 | 执行要求 |
|---|---|---|
| 标题 | 告诉读者这张图回答什么 | 无充分证据时用问题或主题，不把假设写成事实标题；不同图标题结构保持一致 |
| 叙述 | 交代对象、期间、样本与比较口径 | 短句说明必要上下文；不重复标题，不把关键单位埋在长段落里 |
| 绘图区 | 给数据足够空间 | 先给标签与轴预留位置，再确定图形大小；不让圆角、阴影或工具栏吞掉读图面积 |
| 编码 | 将数值／类别映射为位置、长度、色阶等 | 每个编码有明确含义；同一变量跨图保持单位、方向及身份一致 |
| 参考 | 提供目标、基线、区间或事件 | 与实际数据明确区别，说明来源；网格是读数工具，不是装饰背景 |
| 判断 | 指出观察到的差异及其限制 | 靠近相关图形；能回指数据或推导；行动建议与事实描述分开 |
| 来源 | 让图形可以被复核 | 来源、更新时间、样本、缺测、变换方法可查；单独导出仍保留必要口径 |

圆形结论徽标、状态 pill、章节标签属于导航与语义组织，不属于数据尺度。徽标编号由当前文档决定；D2、D6 等原项目标识不能成为所有分析报告的固定编号。状态必须有文字；章节标签不能冒充数据已通过验证的状态。

## 2. 先声明数据，再写标注

### 2.1 一张图的最低输入

在绘图前明确：要回答的问题、观察对象、字段和单位、时间／类别粒度、样本范围、分母与权重、缺失值含义、数据状态、来源，以及准备做的聚合或变换。金额与数量、百分比与百分点、存量与流量、累计与当期不能混在一个未声明的字段里。

图、表、tooltip、导出和判断共用一份规范化数据；显示精度可以不同，底层数值不能各写一份。保留未四舍五入的值用于计算，最后再格式化。比率汇总必须有分子分母或合法权重；没有权重就显示不汇总。零、缺测、不适用、未确认分别编码，不能用同一空字符串处理。

### 2.2 标注的三种证据身份

每条标注先归入以下身份，再选择外形。外形不决定真假：一条虚线可以是测得基线，也可以是假设目标。

| 身份 | 必须能回答的问题 | 可用表达 | 不允许 |
|---|---|---|---|
| `data` 原始记录 | 来自哪个对象、字段、时点和来源 | 原值、观测事件、已提供的目标值；数据尚未核验时一并写状态 | 因为直接来自文件就宣称真实或已核验 |
| `derived` 推导结果 | 使用哪些输入、公式、筛选与缺测处理 | 差额、平均、分位数、排名、合计、依据明确的检测结果 | 手绘一条“平均线”而无计算；用插值冒充观测 |
| `assumed` 假设／情景 | 谁提出、适用条件是什么、何时失效 | 明示“假设”“情景”“待核验分界”的带区或参考线 | 用已完成的状态、肯定式结论或无提示实线伪装事实 |

身份与验证状态是两条轴：人工样本也可包含 `derived` 合计，但仍是演示数据；`data` 不等于 ready。身份要进入原生源或清单，用户界面使用可理解的词，不必显示内部英文枚举。

### 2.3 七种通用标注语法

| 语法 | 绑定对象与使用场景 | 布局与复用约束 |
|---|---|---|
| `anchor` 点锚 | 一个稳定数据 ID 对应的字段／时点；解释某个峰值、异常或重点对象 | 绑定数据身份及坐标，不绑定“第几个点”或写死的屏幕位置；排序、筛选、缩放后仍指向同一对象 |
| `band` 带区 | 一段时间、类别范围或数值域；例如观察窗口、受约束区域 | 存上下界、单位、边界规则和依据；淡底在标记后方，明确是区间而不是另一组面积数据 |
| `range` 区间 | 一个估计／对象的上下界、误差、分位区间 | 绑定中心值和区间定义；端点可读；缺一端不得画成完整区间；不把情景范围标为统计置信区间 |
| `reference` 参照 | 零点、目标、历史基准、平均或政策阈值 | 写清名称与数值；线型区别于数据；来源或计算定义明确；不能为了制造交叉而调节参照 |
| `leader` 引线 | 当文字无法紧邻锚点时，连接锚点与说明 | 从明确锚点到留白区，短路径优先；避免交叉或穿过其他标签；箭头仅在确有方向意义时使用 |
| `status` 状态 | 数据批次、来源、区间或某个结论的状态 | pill 带文字，注明它评价的是数据、工作状态还是业务结果；不能靠色相或圆点单独表达 |
| `takeaway` 判断 | 一条得到支持的观察、解释或行动条件 | 先写观察，再写限制，必要时另列行动；回指对象或标注；不把“同时变化”写成因果 |

机器配方中的 `annotations.required` 要求保留 `target`、`text`、`kind`、`basis`：分别记录绑定对象、用户可读文字、三种证据身份，以及来源／公式／假设依据。数据改变后，推导标注必须重算或失效，不能只移动旧文字。

标注摆放顺序：先轴与直接数值，再关键锚点，再带区／参照的名称，最后解释性文字。遮挡时依次删重复文字、缩短非关键描述、移到边侧留白、使用编号说明；不要挤压图形或把小字继续缩小。移动端可将解释改成编号列表，但锚点和引用关系必须保留。Datawrapper 的标注实现同样强调绑定具体数据行、重排后保持对应和小屏重排；这里采用其原则，不依赖该服务。[Datawrapper 文字与标注](https://www.datawrapper.de/blog/text-in-data-visualizations)、[数据锚定标注](https://www.datawrapper.de/blog/annotations-in-bar-charts)

**迁移示例：** 软件发布报告可以将发布窗口作为 `assumed band`，将日志记录的发布时间作为 `data anchor`，把经过明确统计口径计算的延迟分位数作为 `derived reference`，在旁写“发布后错误率升高，尚未排除流量结构变化”。供应链报告可用完全相同语法表达计划检修窗口、实测停机与产量基准；不需要复制任何房产字段或原图颜色。

## 3. 按问题选图：十七类执行配方

先按问题与数据前提选型，再读取[机器配方](../spec/chart-recipes.json)的 `families`：其中 `question`、`requires`、`encoding`、`must`、`avoid`、`alternative`、`engine` 分别供选型、输入检查、实现和拒绝错误用法。下面的跨领域示例用于说明迁移，不授权编造数据。需要精确比较时优先共同位置与长度；形态图仅在其额外维度确有意义时使用。

### 3.1 折线：变化何时发生

- **问题与输入：** 同一指标随有序时间／连续变量如何变化；须有真实横轴间隔、相同单位及缺测标记。
- **尺度与编码：** 横轴距离按实际时间；缺口断线。纵轴可按分析目的限定范围，但范围必须可见，多图比较时一致。只有观测连续性合理时才连线，平滑不能制造不存在的峰谷。
- **标签与构图：** 系列末端直接命名；实际／目标用线型加文字区分。重点显示端值、突变或特定事件，不给每点加大圆点。为末端名称保留空间。
- **禁用与替代：** 无序类别改条形／点图；主要问题是单期大小用条形；多线难以追踪改小多图。可用于能耗、服务延迟、会员留存或产量趋势。

### 3.2 面积：总量及其变化有多大

- **问题与输入：** 非负量随时间的规模，或具有可加性的组成随时间变化；叠加前确认单位、采样时点和部分能组成整体。
- **尺度与编码：** 面积图通常从零开始；填充代表规模，不是给折线加气氛。堆叠保持固定顺序；内部层不共用基线，不能用它精确比较每层的变化。
- **标签与构图：** 先标总量或主层，浅填充让边界清楚；关键层在可容纳处命名。注明累计值与当期值，避免二者叠加。
- **禁用与替代：** 正负混合、组成不可相加或关注细小差异时改折线／分组条形。可用于能源组成、存储消耗、订单积压规模；不用于无总量意义的评分装饰。

### 3.3 条形／柱形：谁更多，差多少

- **问题与输入：** 同口径类别值或离散时期总量；须有类别身份和可比较量纲。
- **尺度与编码：** 长度从零基线起；正负从共同零点向两边延伸。类别有自然顺序则保留，否则按问题排序；不为了视觉节奏调条长、截断或单独改变尺度。
- **标签与构图：** 长名称优先横条；数值放条端且不遮盖细小条。条间距按真源设置，背景轨道只有在表达容量／上限时才出现。
- **禁用与替代：** 极多类别先给有依据的筛选／分组并保留其余明细；非零窄范围精细比较可用点图。适用于渠道销量、项目成本、缺陷数量和机构规模。

### 3.4 分组条形：多个对象在相同维度怎样比较

- **问题与输入：** 同类别下少量系列的量值，例如方案与基准、不同团队同期表现；字段含类别、系列、数值。
- **尺度与编码：** 共同零点、相同条宽，类别间隔大于组内间隔；系列顺序及颜色跨组固定。
- **标签与构图：** 组名与系列身份清楚，关键差额靠近所比较的一组；同一数据不另加一组无意义连线。图例空间紧张时改小多图，不把组压成密集竖线。
- **禁用与替代：** 系列过多改热图／小多图；要看部分与整体改堆叠；只比起终值可用哑铃点图。适用于产品方案、服务等级、区域预算与实际对比。

### 3.5 百分比堆叠：内部结构如何不同

- **问题与输入：** 各组由互斥且穷尽的部分构成，分母明确；组间统计口径相同，缺项单列而不是悄悄归一化。
- **尺度与编码：** 每条统一表示整体，分段顺序与身份固定；旁边保留总量。若关心数量而非比例，改普通堆叠并保留总量轴。
- **标签与构图：** 百分比与类别相邻；过窄色段将标签外置并提供表格。强调第一段／最后一段的共同基线优势，别宣称中间段的细小变化一眼可比。
- **禁用与替代：** 重叠分类、负数或分母不可比时不能使用；精确比较单个组成项改分组条形。适用于任务状态、用户来源、能源结构和品类组合。

### 3.6 双轴组合：何时值得使用两把尺

- **问题与输入：** 同一横轴对象上确需同时观察两种不同单位，且读者理解两套量纲；必须说明为什么对齐小多图或指数化不足以回答问题。
- **尺度与编码：** 两轴单位、范围和系列对应都可见；一轴有柱／面积时保留其零基线，并审查另一轴零点及范围是否暗示错误比例。禁止靠独立缩放制造“同步”“赶超”或有意义的交叉点。
- **标签与构图：** 尽量用不同编码，如柱与线，并直接标数值和单位；双轴比同轴图更需要留白。图下注明两量纲不能据像素高度互比。
- **禁用与替代：** 面向不熟悉该图的读者、量纲相同、目的是证明相关性，或轴映射说不清时不用。相同量纲用同轴；相对走势用注明基期的指数；关联用散点；共时变化用对齐小多图。可条件用于温度与降水、单量与单价、负载与延迟。

双轴并非从参考中必然继承的优点。其轴范围能改变视觉关系，使用者必须承担额外解释责任。[Datawrapper 双轴准入与误读](https://www.datawrapper.de/blog/dual-axis-charts-guide)

### 3.7 瀑布：如何从起点走到终点

- **问题与输入：** 有明确基准、可加减贡献和终值；全部使用同一基准及单位，小计与总计明确区分。
- **尺度与编码：** 每一浮动条从前一累计值起，增减方向真实；总计回到基线。步骤顺序按时间或解释逻辑决定，不能为了好看让负项悬空或重复计入小计。
- **标签与构图：** 总额与增减值采用不同格式，增减保留正负号；必要的细连接线帮助追踪累计。长类别可转横向；解释文字靠近相关贡献，不穿越多个条。
- **禁用与替代：** 只是互不相关的指标不能相加；部分全为正且仅需比较大小时改条形；大基准让贡献不可见时展示“变化量”并明示基准，不用断轴大柱伪装比例。适用于人数变化、成本拆解、毛利桥接、工期增减。

可核对的路径比堆装饰更重要；这个原则也适用于预算与工程变更。[Datawrapper 瀑布图](https://www.datawrapper.de/blog/waterfall-charts-guide)

### 3.8 点图／散点：精确位置或两个变量的关系

- **问题与输入：** 点图比较类别的单一量值；散点要求每个观测具有成对数值，且缺测配对处理可解释。
- **尺度与编码：** 位置承担主要含义；尺寸默认相同，只有确有第三变量时才用面积编码并给尺度。阈值象限必须标依据，边界不从“图看着居中”决定。
- **标签与构图：** 重点对象直接命名，其余可交互查看并保留可访问表；重叠严重先用透明度、分箱或密度，而不是把点随意挪开。抖动如使用需明示，不能让抖动位置看似真实测量。
- **禁用与替代：** 两轴是无序标签时改矩阵；无法匹配同一对象的两个变量不能画相关性；精确顺序比较可用排序点图。适用于成本与质量、等待时长与满意度、体积与耗能；相关性不等于因果。

### 3.9 直方图：数值分布是什么形状

- **问题与输入：** 连续数值样本或带明确边界的分箱计数；保留样本量、缺测、离群值与分箱方法。
- **尺度与编码：** 横轴是数值区间，不是类别；等宽箱可用频数／频率作高度，不等宽箱须用密度等方式使面积含义正确。多组比较使用相同箱边界及规范化口径。
- **标签与构图：** 写明纵轴为数量、占比或密度；需要时标中位数／分位区间并给计算方法。条之间不加入类别图的大间隔。
- **禁用与替代：** 已聚合的几个均值不能还原分布；样本稀少用点列更诚实；要对比多组中心与离散程度可用箱线图。适用于交付周期、响应时间、消费额、尺寸误差。

### 3.10 箱线图：各组离散程度和异常位置如何

- **问题与输入：** 各组原始样本或完整且可比的分位统计；需要样本量、分位算法、须线及离群值定义。
- **尺度与编码：** 箱体、中心线、须线各自含义必须一致；比较组共用尺度。中心线是中位数还是其他统计量必须明示，不能把须线默认解释成最小最大。
- **标签与构图：** 长组名用横向；显示样本量和必要参考。异常点不因“不好看”删除，密集时用明示的汇总展示。
- **禁用与替代：** 只有均值或主观分数时不可捏造四分位；样本很少优先原始点；关注多峰形态改直方／密度并说明估计方法。适用于实验时长、批次质量、项目费用分布。

### 3.11 热图：哪里集中，哪里不同

- **问题与输入：** 两个有意义的维度形成矩阵，每格是统一定义的数值；缺格与零值可区分。
- **尺度与编码：** 顺序量用连续或分级色阶；有明确中点的偏差用发散色阶。类别色不表示强弱。归一化若按行／列进行，必须说明，不能再跨行比较绝对值。
- **标签与构图：** 行列顺序先遵循时间／业务关系；聚类排序须说明方法。色条必须给单位、端点与缺失样式；密集时关键值直接标，其余给表或可访问详情。
- **禁用与替代：** 精确读数为主且矩阵不大时用带数值表；若色阶差异无法可靠分辨，改小多图／点图。适用于时段负载、指标相关矩阵、工序良率和研究样本表达。

### 3.12 环图：一个整体由哪些部分组成

- **问题与输入：** 非负、互斥、完整的整体分解；分母稳定且总和可校验。中心摘要必须指明是总量还是某类占比。
- **尺度与编码：** 角度／弧长表达比例，内外半径保持一致；排序与起始位置固定。对比不同整体时不要让圆大小暗示未定义的总量编码。
- **标签与构图：** 类别与百分比直接对应，狭窄段用短引线外置；中心文字不堆多个同权指标。状态不够完整时保留“未知”部分并解释分母。
- **禁用与替代：** 类别多、比例接近、需要精确跨组比较或负数时改横条／百分比堆叠。适用于渠道构成、任务状态、缺陷类别；不用于把置信度、得分、完成率混成一个圆。

### 3.13 雷达：多维轮廓与参考在哪里不同

- **问题与输入：** 一组有解释意义的维度，且各维已按明确方法转到可比较尺度；方向一致，越外代表什么清楚。
- **尺度与编码：** 维度顺序与范围固定，所有方案使用同一变换；保留刻度和参考轮廓。不能每个方案独立归一化后比较，不能以封闭多边形面积汇总优劣。
- **标签与构图：** 维度名和关键值靠近各轴；轮廓少量重叠，透明填充仅帮助辨认。标明原始量纲及归一方法的查阅入口。
- **禁用与替代：** 硬性约束与主观评分混合而无变换解释、维度过多或读者要精确差额时，用分组条形、点图或带目标表。适用于已定义评分模型的方案评估、能力画像、实验条件轮廓；不替代合规验算。

### 3.14 极坐标玫瑰：方向或周期中哪里更集中

- **问题与输入：** 方向角、时钟／季节等真正首尾相接的变量，加频率或其他明确度量；声明分箱、方向定义与分母。
- **尺度与编码：** 角向位置有固定顺序，径向刻度明确；声明长度还是面积表示数值。若等角扇形要求面积与值成正比，半径必须作对应变换，不能让半径正比后又声称面积可比。
- **标签与构图：** 方位、单位、主导项和频率可读；静风、缺失或无方向数据另列，不塞入某方向。标速度时给独立编码或文字，不把频率半径误称风速。
- **禁用与替代：** 无序类别改横条；关注准确排名也用横条；仅为了仪表盘装饰不用极坐标。适用于风向、方向性缺陷、日内事件分布和周期负载。

### 3.15 数据表：必须逐项核对或继续计算

- **问题与输入：** 用户要查某个精确值、比较多个字段或追溯明细；字段定义、单位、精度与缺失语义齐全。
- **尺度与编码：** 数字右对齐、等宽数字，小数精度按口径统一；分类左对齐。行内条形必须共用尺度，小趋势线必须共用时间窗；它们不能替换精确数值。
- **标签与构图：** 表头说明单位与排序；合计和明细区分；使用原生表格、caption、scope。移动端按字段名逐项展开；不能把整个表截图缩到不可读。
- **禁用与替代：** 主要任务是发现趋势／分布时，以图为主、表作证据；列太多先按任务分组，不在多层卡片里挤压。适用于预算、实验指标、项目状态、订单与设备参数。遵守[对比表契约](../components/comparison-table.json)。

### 3.16 小多图：多个对象怎样在同一语法下比较

- **问题与输入：** 同一个指标／关系在地区、产品、时期或方案间重复，字段与统计方法可比。
- **尺度与编码：** 比较绝对大小时共享轴范围、基准与时间窗；若采用独立范围看形态，必须显著标明，禁止据形状比较量级。颜色代表同一系列，不为每块小图随机换色。
- **标签与构图：** 每图短标题，轴与图例只做必要重复；面板顺序按问题组织，行列间距一致。响应式换行后阅读顺序保持，相关参照在每个面板位置一致。
- **禁用与替代：** 数据口径不同不能伪装同组；每图过小则减少同屏数量或改选择器；总体分布问题可用箱线／热图。适用于跨店经营、版本性能、设备监测、实验组比较。

### 3.17 区间／误差图：估计有多不确定，范围重叠吗

- **问题与输入：** 点估计及真实上下界，或明确的情景范围；须标置信／可信／预测／标准差／分位等区间类型及计算方法。
- **尺度与编码：** 中心点与端点共用尺度，非对称区间按实际上下界绘制。时间连续区间可用带状，分类比较可用点加误差线；区间透明度不代表概率高低。
- **标签与构图：** 区间定义靠近图标题／图例，关键上下界可查。参考线不要盖住中心点；相邻区间错位仅为排版时不得改变对应类别。
- **禁用与替代：** 无不确定性计算或上下界时不画误差；主观“乐观／保守”应称情景；不能只凭区间是否重叠自动断言统计显著性。可用于需求预测、工期估计、模型误差和样本统计。

## 4. 排版、笔画和组合布局

### 4.1 参数如何落地

所有规范值以 [chart-recipes.json](../spec/chart-recipes.json)为准，引用时记录使用的版本／文件，避免在多个临时 CSS 中另立常量。规范中存在的字段不等于渲染器已经自动读取；当前消费范围见[参考实现的调用边界](#55-参考实现的调用边界)。字体和颜色应与 Gary Token 对齐，图表参数只控制图内层级，不替换全站正文规则。

| 参数族 | 必须配置／读取什么 | 判断方法 |
|---|---|---|
| 排版 | 图标题、叙述、轴标签、直接值、注释、来源各自字号、字重、行高与最小可读字号 | 在最终显示尺寸检查 computed size 和截图；SVG 源字号大但整体被缩小不算满足 |
| 留白 | 外壳内边距、标题到图、轴标签到绘图区、图例／注释间隔、图到判断／来源间隔 | 标签不能侵入主图形；相关内容近于无关内容；多个图的轴线与内容边界有对齐依据 |
| 笔画 | 主数据线、参考线、网格线、引线、区间端点、点标记的等级 | 数据最醒目；参考和网格退后但仍可辨；导出缩放后不丢线，不用粗描边掩盖几何错误 |
| 对比度 | 普通文字、重要图形和交互状态分别检查的阈值 | 按最终背景计算，含透明混合、深浅主题及打印；不能只测前景色常量 |
| 密度 | 同图系列／类别／标注容量与响应式策略 | 超容量优先改图、分组或小多图；不默认省略数据、不无限缩字 |
| 坐标 | 轴边距、刻度密度、零线／参考线样式、区间边界与标签碰撞策略 | 数值关系不受容器宽度变化影响；网格只沿需要读数的方向出现 |

轴范围与零基线属于数据解释，不属于审美自由度。条形的零基线、缺测不连线与时间刻度一致性，可核对 [Carbon 轴与标签](https://carbondesignsystem.com/data-visualization/axes-and-labels/)。字体大小与密度必须看最终任务，不因追求“清爽”把必要标签全部隐藏。

### 4.2 响应式处理顺序

先缩减非必要刻度和重复图例，接着将长标签改横向布局、将解释移至编号说明、将多系列拆小多图。表格转带字段名的逐行布局。仍需精读复杂工程图时，可在有清晰提示的图区域提供局部缩放／横向阅读，但必须保留可访问明细，页面本身不横溢，关键判断和来源不藏在画外。

不以“手机版”名义删去风险、区间、负值或数据状态。Desktop、手机、打印可以重排，不能改变问题、身份、数据、尺度含义与判断条件。图与说明之间的 anchor 引用要随重排重新定位。

## 5. 颜色、材质、动态与输出

### 5.1 颜色先定义语义

先判断颜色是在区分类别、编码有序量、表示相对中点的偏差，还是表达状态，再选择对应色系。完整色彩选择与 Apple／Google 设计原则的转译见[图表色彩体系](CHART_COLOR.md)；可执行角色与深浅主题仍以 [chart-recipes.json](../spec/chart-recipes.json) 的 `colorSystem`、`themes` 为真源，本页不另立色板。中性承担上下文，强调色指向本图的重点；同一页面同一对象不随图型换色。[Carbon 数据可视化配色](https://carbondesignsystem.com/data-visualization/color-palettes/)

GarchOS 样本里的 mint、rust、gold、teal 是该样本的局部映射。迁移时先写语义与领域约定，不规定“折线永远金色”“好结果永远薄荷色”；金融涨跌、医学风险或业务异常需按该任务明确口径。数值为正也不必然是好事，例如延迟或缺陷增加。渐变、阴影和发光不得替代数值编码，也不得使图形看起来有未定义的第三维。

### 5.2 三种表面已经批准，图表不因批准而玻璃化

- `data-gary-surface="solid"`：密集图表、精确表格、长正文。刻度、数据色和对比度稳定。
- `data-gary-surface="frosted"`：摘要、导航、判断。与数据区域并列组织，避免玻璃嵌套。
- `data-gary-surface="optical"`：短内容、媒体与展示。前景文字和数据不加滤镜，不做 tilt。

只有一个默认点阵；图内参考网格只为读数。鼠标点阵、卡片高光、波面视差默认关闭，只在 `Background` 明确开启、根属性 `data-gary-pointer-effects="on"` 时允许；减弱动态优先。`data-gary-light-scope` 只声明共享光场范围，不自行开启动效。完整调用与材质边界见 [VISUAL_EXPRESSION.md](VISUAL_EXPRESSION.md)。

### 5.3 动态必须解释变化

静态状态先完整可读；真实数据更新才使用有界过渡，不用数字滚动装作分析深度。动画不得造成暂时错误的合计、顺序或比例；状态提示向辅助技术报告最终结果，避免逐帧播报。讲述步骤可以分段播放，但要支持暂停、完整呈现与重播；减弱动态、打印、导出和页面不可见时，保持稳定结果。时长读取场景真源，不为每张图另设一套节奏。

### 5.4 按交付物选择输出

| 交付用途 | 选择路径 | 必须保留 |
|---|---|---|
| 常规定量图、需要筛选与更新 | 已固定的本地 ECharts 与 Gary 适配器 | 原生数据与配置、来源、替代数据表、异常状态 |
| 固定版式、复杂引线、可编辑矢量研究图 | 原生 SVG；共享数据驱动坐标和注释 | 文本节点、viewBox、title／desc、可复算的几何；不能以截图替代语义 |
| 研究论文、科学图、需精确版式的报告 | 现有绘图库生成独立矢量／高分辨率输出 | 轴、图例、误差定义、方法、字体与最终版面检查 |
| HTML 报告与可复制页面 | 稳定 HTML＋图形源＋数据表 | 断网可用的本地依赖、移动端与键盘路径 |
| SVG／PNG／PDF 单独分享 | 从同一数据和当前主题生成独立产物 | 必要标题、单位、图例、注释、来源和状态；检查裁切、细线、透明背景及字体 |

`SVG`、`Canvas`、`ECharts` 是实现选择，不决定图表正确与否。框架换成 React 也必须复用同一语义；不因换框架再发明另一套颜色与坐标规则。复杂关系图走 Archify／Markmap 等既有路由，不能用统计图外形伪装没有度量的数据关系。

### 5.5 参考实现的调用边界

[chart-recipes.js](../patterns/shared/chart-recipes.js)是浏览器原生 SVG 参考实现，不是 Visual Adapter 新增引擎。它公开 `window.GaryChartRecipes`：

| 调用 | 输入与返回 | 边界 |
|---|---|---|
| `validate(type, config)` | 校验输入，成功返回 `true`，不合法时抛错 | 只检查已实现的五类输入，不执行全部 17 类规范或判定业务真实性 |
| `render(type, config, { policy, theme })` | 返回 SVG 元素；`policy` 为机器规则对象，`theme` 为 `dark` 或 `light` | 每次读取输入计算几何，不自行挂载、监听主题或导出；标签放不下时明确拒绝，不截断或静默漏项 |
| `table(type, config)` | 从同一输入返回有 caption、行列标题的原生 table | 负责值和语义结构；宿主仍须提供表格样式、手机逐行布局与键盘路径 |

目前 `type` 仅支持 **`combo / waterfall / donut / radar / rose`**，对应条件双轴、瀑布、环图、雷达与极坐标玫瑰五种参考。其他图型按 `families[].engine` 复用既有 ECharts、原生表格或现有绘图库；不能把 17 类规范清单宣传成 17 个已实现组件。图表库也不会自动给数据生成可信判断。

当前实现的规则消费范围如下；其余字段仍是作者与验收者须执行的约束，不能仅凭 `render()` 成功视为满足：

| 实装范围 | 当前读取内容 |
|---|---|
| 自动读取 | `themes[theme]` 中当前图形使用的背景、文字、网格、语义／类别角色色；`geometry` 的宽高与最小宽度；`typography.family / label / small / metric`；`strokes.data / reference / guide / marker`；`fills.area / barTop / barBottom / band` |
| 作者实现与审查 | `spacing`、其余 typography 阈值、`grid`、`contrast`、七层 `anatomy`、完整 `annotations` 协议、布局／动态／导出要求及各图型准入条件；不能假定改一处 JSON 就会自动改变全部外壳间距或通过对比度检查 |

完整 `colorSystem` 还服务于其他图型的类别、顺序、发散和状态选色。当前五种 SVG 不会自动把所有色阶应用到每张图，也不会自动做色觉模拟或对比度验收；选色、稳定映射与实际背景检查仍由调用方负责。

七种标注是完整设计语法，当前 SVG 模块未提供通用 `annotations[]` 渲染器。`combo.annotation` 只接受 `start / end` 类别名称、`label / kind / basis` 和可选 `detail`，据此计算带区与说明位置；它映射到规范的目标、文字和依据，而不是把规范字段直接原样传入。其他形态中的数值、参考轮廓或页外状态也不代表全部七种标注均已自动实现。推导判断由调用方重算或明确失效，不能让旧判断跟着新图继续显示。

调用输入还须保留以下语义；完整形状可对照 [cases.json](../examples/demo0909/cases.json)：

- `donut.items[]` 每项显式提供稳定的 `key` 和 `role`；排序变化时保留原类别角色，不能按当前数组次序重新着色。
- 使用 `radar.reference` 时同时提供 `referenceMeta: { label, kind, basis }`，说明参考轮廓名称、`data / derived / assumed` 身份和来源／推导／假设。参考数组与维度一一对应，不能默认一圈参考线就是已证实标准。
- 使用 `waterfall.scenarios[]` 时，每项提供 `kind`、`basis`，将独立情景与实际累计区分。累计量供图与表共用，计算过程不逐项四舍五入；显示精度不回写原值。精确金额由业务层换算为最小计量单位输入，并保证在 JavaScript 安全整数范围内，不能用图形格式化修正账目误差。

下面是**放在仓库根目录 HTML 内**的最小调用，用真实案例结构演示同源图表和数据表。通过本地预览服务打开；移到其他目录须调整资源路径。`cases.json` 只是人工验证输入，不是业务数据接口。

```html
<link rel="stylesheet" href="tokens/base.css">
<div id="chart" data-gary-surface="solid"></div>
<div id="values" data-gary-surface="solid"></div>
<script src="patterns/shared/material.js"></script>
<script src="patterns/shared/chart-recipes.js"></script>
<script type="module">
  const chart = document.querySelector('#chart');
  const values = document.querySelector('#values');
  try {
    const responses = await Promise.all([
      fetch('spec/chart-recipes.json'),
      fetch('examples/demo0909/cases.json')
    ]);
    if (responses.some(response => !response.ok)) throw new Error('图表输入未加载');
    const [policy, cases] = await Promise.all(responses.map(response => response.json()));
    const type = 'donut';
    const config = cases.types[type][0].config;
    values.replaceChildren(GaryChartRecipes.table(type, config));
    const theme = document.documentElement.dataset.garyTheme === 'light' ? 'light' : 'dark';
    chart.replaceChildren(GaryChartRecipes.render(type, config, { policy, theme }));
  } catch (error) {
    chart.textContent = `图形未生成：${error.message}`;
  }
</script>
```

这段代码只演示一次加载与挂载。生产页面还要把问题、叙述、状态和判断按七层结构放在图旁；主题、案例或打印模式改变后重新用同一配置生成相应图形。若输入无效，显示错误并明确上一份结果的身份；不能让当前标题配上旧图。独立 SVG、HTML、PNG、PDF 的产物检查和正式清单仍走既有交付路径，不因这个浏览器模块改变。

[cases.json](../examples/demo0909/cases.json)每类提供跨领域输入：客服与设施的双轴、项目产能与能源收支的瀑布、状态与经费构成的环图、服务与产品的不同维数雷达、一天周期与建筑朝向的玫瑰。案例中的类别数量、单位、量级、正负与缺测用于检验迁移；每条仍是人工演示，状态不等于真实业务已核验。页面呈现与样本本身不预先证明测试通过，须对当前实现执行后面的验收要求。

## 6. Agent 执行顺序

1. **写清问题与读者。** 用一句话界定任务；记录交付媒介、可用空间、读者需要精读还是概览。不要从“需要一个漂亮雷达图”反推不存在的数据。
2. **检查原始数据。** 识别字段、单位、状态、来源、缺测、重复、分母、权重、样本和时间范围；不满足前提时报告缺口或换图。
3. **选型并说明排除理由。** 从机器配方选一个主要图型；双轴、雷达、玫瑰等须满足准入条件。记录可比尺度与参考基准，注明为何不使用更简单的替代。
4. **建同源数据与标注。** 计算一次，用于图、表、导出和判断。每条注释声明 data／derived／assumed，并保留绑定对象、来源或推导；先校验总和与单位，再写 SVG／option。
5. **建立七层结构。** 先完成静态标题、绘图区、尺度、标签与来源，再加必要判断与交互。读取 Token 和图表真源；复用既有本地依赖。
6. **做真实尺寸排版。** 检查桌面、手机与目标输出尺寸；先解决遮挡、读数和密度，再处理外壳。数据区域用 Solid，鼠标光影保持默认关闭。
7. **验证迁移能力。** 替换为不同领域的输入，再改变类别数量、次序、数值范围和正负情况；渲染器不改代码，图形与推导标注应自动重算或明确拒绝不适用输入。仅换文字、其余仍是固定坐标，不能称为可复用配方。
8. **验证内容与产物。** 核对数值／单位／缺口／范围／标注绑定；实际打开导出，检查无失字、裁切与语义变化。控制台无错不能代替这些检查。
9. **记录交付边界。** 给出原生源、数据、所用配方、已验证尺寸／主题／格式和未验证部分。审美接受不等于数据核验；新的通用规则回到母本，个例保持项目作用域。

## 7. 验收：出现以下任一项不得通过

| 必须失败的情况 | 要求的修正或证据 |
|---|---|
| 图、表、tooltip、导出或结论的数值不一致 | 回到同一数据源生成，证明聚合、舍入和单位一致 |
| 数据状态不明，演示／假设被当事实，缺测被填零或连线 | 区分 data 身份与核验状态；显示缺口，移除无依据断言 |
| 单位、分母、权重、样本范围或时间口径缺失 | 补足可复核定义；无法补足则不画相关比较 |
| 柱／面积非零基线造成比例误读，轴变换未声明，双轴靠范围制造关系 | 修正尺度或换图；说明范围选择与剩余限制 |
| 堆叠不闭合、瀑布不守恒、环图部分不互斥、区间上下界无来源 | 修正数据模型；不可通过美化掩盖 |
| 雷达各方案独立归一、凭面积排名；玫瑰未声明径向编码 | 固定变换并逐维／逐向核对，或改用更直接图型 |
| 排序、筛选或响应式后标注指错对象 | 将 anchor 绑定稳定 ID／域值，重算坐标并验证 |
| 换领域、类别数量或数据范围就要修改渲染器中的业务标签、条长和引线位置 | 分离输入、领域注释和通用几何；用第二组领域数据及边界输入证明复用 |
| 关键标签遮挡、字号低于真源下限、颜色不足以辨认或仅靠 hover 获得必要信息 | 重排、直接标注、给可访问明细，检查实际尺寸与对比度 |
| 图表被折射、文字被滤镜、背景光影改变语义色，鼠标装饰默认开启 | 恢复数据 Solid 层与显式光影开关；验证减弱动态 |
| 独立导出丢失单位／图例／来源／状态，文字裁切或颜色与屏幕语义不同 | 修复导出布局并重新打开产物；不能只检查下载成功 |
| 仅凭静态源、JSON 校验或无控制台错误就宣布视觉完成 | 提供真实浏览器及目标导出的内容与视觉检查证据 |

检查阈值与适用条件仍以[机器规则](../spec/chart-recipes.json)为准。本文和参考页面不预先证明任何新项目通过；每次交付都要验证当前数据、实际版面和目标输出。
